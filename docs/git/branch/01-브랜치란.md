- **브랜치(Branch)**는 Git에서 코드 관리의 흐름을 나누는 중요한 개념이에요.
- 단어 자체가 '나뭇가지'라는 뜻이고, 실제로 Git의 커밋 히스토리 구조가 뿌리에서 여러 가지로 갈라지는 나무와 비슷해요.

## 브랜치를 쓰는 이유

- 하나의 프로젝트 안에서 무료 버전, 유료 버전 등 서로 다른 버전을 만들고 관리하기 위해 브랜치를 활용해요.
- 서로 다른 두 프로젝트를 따로 만들지 않고, 하나의 코드베이스 안에서 브랜치로 작업 흐름을 나눌 수 있어요.

## 브랜치의 특징

- 각 브랜치에서 작업한 내용은 서로 독립적이에요.
- 예를 들어, premium 브랜치에서 파일을 수정 후 커밋해도 master 브랜치에는 영향을 주지 않아요.
- 브랜치를 바꿔가며 각각의 버전을 따로따로 관리할 수 있어요.

## 브랜치 명령어

### 현재 브랜치 확인

```bash
git status
```

→ `On branch master`와 같이 현재 사용할 브랜치가 표시돼요.

### 브랜치 목록 확인

```bash
git branch
```

→ 현재 위치한 브랜치 옆에는 `*` 표시가 있어요.

### 브랜치 생성

```bash
git branch 브랜치이름
```

→ 예시:

```bash
git branch premium
```

(예시로 유료 버전 작업용 브랜치 생성)

### 브랜치 삭제

```bash
git branch -d test
```

- 브랜치를 삭제하고 싶을 때는 `git branch -d 브랜치명`을 사용해요.
- 여기서 `d`는 delete(삭제)의 줄임말이에요.

### 브랜치 이동

```bash
git checkout 브랜치이름
```

- 기존 브랜치로 이동할 땐 `git checkout 브랜치명`을 써요.

→ 예시:

```bash
git checkout premium
(프리미엄 브랜치로 이동함)
```

### 브랜치 생성후 바로 이동

```bash
git checkout -b test
```

- 브랜치를 만들고 바로 이동하고 싶을 때는 `git checkout -b 브랜치명`을 사용해요.

### 파일 추가 및 커밋

```bash
git add .
git commit -m "커밋 메시지"
```

## 정리

- 브랜치 = 코드 관리 흐름을 나누는 나뭇가지. 각 브랜치의 작업은 서로 독립적
- `git branch 이름` 생성 / `git branch -d 이름` 삭제
- `git checkout 이름` 이동 / `git checkout -b 이름` 생성 후 바로 이동
