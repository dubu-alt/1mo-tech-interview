---
title: "이미지 빌드와 Docker Hub 배포"
---

내가 만든 애플리케이션을 컨테이너로 돌리려면, 먼저 그 애플리케이션을 담은 **이미지**를 직접 만들어야 합니다. 이 과정을 **빌드(Build)**라고 부릅니다.

### 빌드에 필요한 두 가지
빌드에는 **Dockerfile**과 **빌드 컨텍스트**가 필요합니다. Dockerfile은 "이미지를 어떻게 만들지" 적어둔 설계도이고, 빌드 컨텍스트는 그 설계도대로 재료(소스코드 등)를 가져올 시작 위치입니다.

### 빌드 명령어
공식적으로는 기존의 `docker image build` 대신 **`docker buildx build`**를 표준으로 사용합니다.

```
docker buildx build -t username/이미지명:태그 .
```

| 옵션 | 의미 |
|---|---|
| `-t` | 이미지 이름과 태그 지정 |
| `--build-arg` | 빌드 시점에 넘겨줄 변수 |
| `-f` | Dockerfile 경로 지정 (기본값은 `Dockerfile`) |
| `--pull` | 베이스 이미지를 항상 최신으로 새로 받아옴 |

### 빌드 컨텍스트는 왜 보통 `.`일까
빌드 컨텍스트는 대부분 소스코드 최상위 경로로 지정합니다. 그 위치에서 빌드 명령어를 실행해야 경로가 꼬이지 않고 헷갈릴 일이 없습니다.

### 빌드 로그 읽는 법
빌드를 실행하면 로그에 `1/4`, `2/4`처럼 진행 상황이 찍히는데, 이는 Dockerfile의 각 명령어가 레이어 하나씩 만들어지는 과정을 보여주는 겁니다.

### 만든 이미지 확인하고 배포하기
빌드가 끝나면 `docker image ls`로 내 컴퓨터에 잘 만들어졌는지 확인합니다. 배포는 Docker Hub에 로그인한 뒤 진행하며, 태그를 여러 개 한 번에 올리고 싶다면 `docker image push -a username/이미지명`을 사용하면 됩니다. 업로드 후에는 Docker Hub 사이트에서 이미지와 태그가 정상적으로 올라갔는지 확인할 수 있습니다.

**정리 흐름**: Dockerfile 작성 → `docker buildx build`로 이미지 빌드 → 로컬에서 확인 → Docker Hub로 배포
