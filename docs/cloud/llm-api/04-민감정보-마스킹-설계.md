`git diff`에는 실수로 넣은 API Key, 토큰, 이메일이 섞여 있을 수 있습니다. 이 diff를 그대로 외부 LLM API에 보내면 비밀이 제3자 서버로 넘어갑니다. ai-gitgen의 `--safe-mode`는 보내기 전에 이런 값을 정규식으로 찾아 가립니다.

## 무엇을 가리나

| 대상 | 패턴 예 |
|---|---|
| OpenAI/Anthropic 계열 키 | `sk-...`, `rk-...` |
| GitHub 토큰 | `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_` |
| AWS Access Key | `AKIA...` |
| Slack 토큰 | `xoxb-`, `xoxa-` 등 |
| Google API Key | `AIza...` |
| Authorization 헤더 | `Authorization: Bearer ...` |
| JWT | `eyJ...`로 시작하는 점 3부분 |
| 이메일 | `name@example.com` |
| `.env` 비밀값 | 변수명에 KEY, SECRET, TOKEN, PASSWORD가 들어간 줄의 값 |

찾은 값은 `[MASKED:GitHub 토큰]`처럼 **종류 이름을 남겨서** 바꿉니다. LLM은 "여기 토큰이 바뀌었다"는 맥락은 알 수 있고 실제 값은 모릅니다.

## 맥락은 남기고 값만 가리기

```
SECRET_KEY=abc123          →  SECRET_KEY=[MASKED:비밀 설정값]
Authorization: Bearer x.y  →  Authorization: [MASKED:Authorization/Bearer 헤더]
```

`.env` 줄과 Authorization 헤더는 정규식 그룹으로 앞부분(`SECRET_KEY=`, `Authorization: `)을 그대로 두고 값만 바꿨습니다. 그래야 커밋 메시지에 "시크릿 키 설정 변경" 같은 설명이 나올 수 있습니다. 실행하면 `마스킹: GitHub 토큰 1건`처럼 몇 건을 가렸는지 보여 줍니다.

## 순서: 가리고 나서 자르기

safe-mode는 마스킹과 함께 전송량도 줄입니다(기본 10개 파일, 200줄). 이때 순서를 **마스킹 먼저, 자르기 나중**으로 고정했습니다.

```python
masked, found = mask_sensitive_text(diff)
limited, note = limit_diff(masked, max_files, max_lines)
```

자르기를 먼저 하면 잘린 경계에 키의 일부만 남을 수 있습니다. 예를 들어 `sk-abcdefgh...`가 중간에서 잘려 짧아지면 "8자 이상" 같은 패턴에 걸리지 않아 일부가 그대로 나갈 수 있습니다. 전체 원문에서 먼저 가리면 이런 틈이 생기지 않습니다.

파일 수 제한은 diff를 `diff --git` 헤더 기준으로 나눠서 파일 단위로 자르고, 줄 수 제한은 그 뒤에 적용합니다.

## 한계

- **정해 둔 모양만 찾습니다.** 접두사가 없는 비밀번호나 새로운 형식의 키는 그대로 나갈 수 있습니다.
- 반대로 이메일처럼 넓은 패턴은 예제 문서의 주소까지 가립니다.
- **기본값이 꺼져 있습니다.** `--safe-mode`를 붙여야만 동작합니다. 안전을 생각하면 기본으로 켜 두는 편이 낫습니다.
- 그래서 원칙은 **비밀을 애초에 커밋하지 않는 것**이고, safe-mode는 실수를 한 번 더 막는 장치입니다.

## 면접에서 나올 만한 질문

### Q. diff를 외부 AI에 보낼 때 민감정보는 어떻게 막았나요?

외부 전송의 위험을 알고 있는지, 안전장치의 한계도 아는지 봅니다.

> `--safe-mode`에서 키·토큰·JWT·이메일·`.env` 비밀값을 정규식으로 찾아 `[MASKED:종류]`로 바꾸고 나서 보냈습니다. `.env` 줄은 변수명은 남기고 값만 가려서 AI가 맥락은 알 수 있게 했습니다. 전송량을 자르는 것보다 마스킹을 먼저 해서 잘린 경계에 키 일부가 남지 않게 했습니다. 다만 정해 둔 패턴만 잡을 수 있고 기본값이 꺼져 있어서, 비밀은 애초에 커밋하지 않는 것이 먼저라고 생각합니다.

### 꼬리질문

- 다시 만든다면 무엇을 바꾸겠어요?
  → safe-mode를 기본으로 켜고, 패턴 대신 문자열의 무작위성(엔트로피)이 높은 값을 잡는 방식도 함께 쓰겠습니다. 엔트로피 방식은 직접 구현해 보지는 않았습니다.
