프롬프트로 양식을 정해 줘도 LLM이 항상 그대로 지키지는 않습니다. ai-gitgen은 받은 텍스트를 **그대로 믿지 않고** 규칙으로 검사한 뒤, 고칠 수 있는 것은 고치고 나머지는 경고로 알려 줍니다.

## 실제로 나올 수 있는 어긋남

- 답을 ```` ``` ```` 코드블록으로 감싸서 돌려줌
- 커밋 제목이 너무 김
- PR 제목을 `TITLE:` 줄로 달라고 했는데 빠뜨림
- `## Why` 대신 `### Why`, `## What:` 같은 변형 헤더를 씀
- 필수 섹션이 없거나 섹션 안에 불릿이 없음

## 규칙

| 대상 | 규칙 | 어기면 |
|---|---|---|
| 커밋 제목 | 50자 권장, 72자 최대 | 50자 초과는 경고만, 72자 초과는 자름 |
| 커밋 본문 | 불릿(`-`) 사용 | 경고 |
| PR 제목 | `TITLE:` 줄, 80자 최대 | 없으면 첫 줄을 제목으로, 80자 초과는 자름 |
| PR 본문 | `## Why` / `## What` / `## How to Test` | 변형 헤더는 표준으로 바꿈, 누락은 경고 |
| PR 섹션 | 섹션마다 불릿 1개 이상 | 경고 |

50자와 72자는 Git 커뮤니티에서 흔히 쓰는 관례입니다. 한 줄 로그나 GitHub 목록에서 제목이 잘리지 않는 길이입니다.

## 처리 순서

```
코드블록 펜스 제거
 → 제목 찾기 (PR은 TITLE: 줄, 없으면 첫 줄)
 → 제목 길이 검사·자르기
 → 섹션 헤더 정규화 (### Why, ## What: → ## Why, ## What)
 → 필수 섹션·불릿 검사 → 경고 목록
 → 제목 + 본문 다시 조립
```

헤더 정규화는 정규식 하나로 합니다.

```python
pattern = re.compile(rf"^#+\s*{re.escape(name)}\s*:?\s*$", re.IGNORECASE | re.MULTILINE)
body = pattern.sub(section, body)
```

`#`의 개수, 끝의 콜론, 대소문자 차이를 모두 받아서 `## Why`처럼 하나로 맞춥니다. `TITLE:`도 `**TITLE**:`이나 전각 콜론 `：`까지 허용했습니다.

## 거절하지 않고 고치는 이유

검사 결과는 `ok`, `warnings`, `fixed_text` 세 가지를 담아 돌려줍니다. 제목이 아예 없을 때만 실패로 처리하고, 나머지는 고친 텍스트와 경고를 함께 보여 줍니다.

- 다시 생성하면 **API를 한 번 더 부르는 비용**이 듭니다.
- 형식이 조금 어긋나도 내용은 쓸 만한 경우가 많습니다.
- 결과는 어차피 **초안**이고 마지막 판단은 사람이 합니다. 경고(`[INFO] 검증 경고: ...`)를 보고 옵션을 바꿔 다시 실행할지는 사용자가 정합니다.

## 한계

- 형식만 검사합니다. 커밋 메시지 내용이 실제 변경과 맞는지는 확인하지 못합니다.
- 길이를 넘으면 단어 중간에서도 잘립니다.

## 면접에서 나올 만한 질문

### Q. LLM 응답의 형식은 어떻게 보장했나요?

프롬프트만 믿었는지, 출력 쪽에서도 검증했는지 봅니다.

> 프롬프트로 양식을 정해 주고, 받은 뒤에 한 번 더 검사했습니다. 코드블록 펜스를 벗기고, 커밋 제목은 72자, PR 제목은 80자를 넘으면 자르고, `### Why` 같은 변형 헤더는 정규식으로 `## Why`로 맞췄습니다. 필수 섹션이나 불릿이 없으면 경고만 띄웠습니다. 다시 생성하면 API를 한 번 더 써야 하고 결과도 초안이라서 고칠 수 있는 건 고치고 판단은 사람에게 맡겼습니다.

### 꼬리질문

- 응답을 JSON으로 받으면 더 쉽지 않나요?
  → 구조는 더 확실해지지만 이 도구는 사람이 바로 읽고 붙여 넣는 텍스트가 목적이라 텍스트 양식으로 받았습니다. JSON 출력 방식은 시도해 보지 않았습니다.
