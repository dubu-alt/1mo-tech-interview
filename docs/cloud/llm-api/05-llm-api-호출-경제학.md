LLM API는 보내고 받는 토큰 수만큼 비용(또는 무료 할당량)이 줄어듭니다. ai-gitgen은 한 번 실행할 때 몇 번 부르는지, 얼마나 보내는지를 의식해서 만들었습니다.

## 토큰과 비용

- **입력 토큰**: system 프롬프트(양식 규칙) + user 프롬프트(git status, diff). diff가 길수록 늘어납니다.
- **출력 토큰**: 생성된 커밋 메시지나 PR 초안. `--max-tokens`(기본 800)로 상한을 정합니다.
- 비용은 대략 `(입력 + 출력 토큰) × 모델 단가`입니다. Codyssey 콘솔처럼 모델마다 차감 배수가 다른 곳도 있습니다.

## 한 번 실행에 한 번 호출

`commit`과 `pr`은 각각 **API를 딱 1번** 부릅니다. 파일마다 따로 요약을 받아 합치는 방식도 가능하지만, 그러면 호출 수가 파일 수만큼 늘고 공통 프롬프트도 매번 다시 보내야 합니다. 그래서 diff 전체를 한 번에 보내고 결과도 한 번에 받습니다.

호출 횟수는 클라이언트가 세어서 실행 마지막에 보여 줍니다.

```
[INFO] AI API 호출 횟수: 1회
```

변경 사항이 없으면 API를 부르지 않고 바로 끝내고, API Key가 없을 때도 요청 전에 멈춥니다. **쓸모없는 호출을 아예 만들지 않는 것**이 가장 싼 방법입니다.

## 보내는 양 줄이기

| 방법 | 효과 |
|---|---|
| `--safe-mode --max-files N --max-lines N` | diff를 파일 수·줄 수로 잘라 입력 토큰을 줄임 (기본 10개, 200줄) |
| `--max-tokens` | 출력 길이 상한. 너무 작으면 PR 본문이 중간에 잘림 (PR은 500~1000 권장) |
| `--model gemini-3-flash` | 기본 모델을 싸고 빠른 Flash 계열로 둠 |
| `--temperature 0.3` (기본) | 형식을 잘 지켜서 다시 실행할 일을 줄임 |

전송량 제한은 safe-mode를 켰을 때만 적용됩니다. safe-mode 없이 실행하면 diff 전체가 그대로 갑니다.

## 다시 생성하지 않는 설계

LLM 응답이 양식을 조금 어겨도 자동으로 다시 요청하지 않고, 자르고 정규화한 뒤 경고만 띄웁니다([LLM 출력 검증과 후처리](./03-llm-출력-검증과-정규화)). 자동 재생성을 넣으면 품질은 조금 오를 수 있지만 호출 수가 예측할 수 없게 늘어납니다.

결과는 초안으로만 출력하고 `git commit`, `git push`, GitHub PR 생성은 하지 않습니다. 사람이 읽고 고친 뒤 직접 반영합니다.

## 한계

- 전송량 제한이 safe-mode에 묶여 있어서, 큰 diff를 safe-mode 없이 보내면 입력 토큰이 그대로 커집니다.
- 줄 수로 자르면 뒤쪽 파일의 변경은 AI가 아예 보지 못해 메시지에서 빠질 수 있습니다.
- 실제 토큰 사용량(응답의 `usage`)은 읽지 않고 호출 횟수만 보여 줍니다.

## 면접에서 나올 만한 질문

### Q. LLM API 비용은 어떻게 관리했나요?

호출 수와 입력량을 의식하고 설계했는지 봅니다.

> 한 번 실행에 API를 한 번만 부르게 하고, 마지막에 호출 횟수를 출력했습니다. 변경이 없거나 키가 없으면 요청 전에 끝냅니다. diff는 safe-mode에서 파일 10개, 200줄로 자를 수 있고, 기본 모델은 저렴한 Flash 계열로 두었습니다. 양식이 어긋나도 자동으로 다시 요청하지 않고 후처리로 고쳐서 호출 수가 늘지 않게 했습니다.

### 꼬리질문

- diff를 자르면 결과 품질이 떨어지지 않나요?
  → 떨어질 수 있습니다. 뒤쪽 파일이 빠지면 메시지에서도 빠집니다. 다음에는 파일별 변경 줄 수 요약(`git diff --stat`)을 항상 함께 보내서 전체 범위는 알게 하겠습니다. 직접 구현해 보지는 않았습니다.
- 토큰을 더 정확히 관리하려면요?
  → 응답의 `usage` 필드로 실제 토큰 수를 기록하고 보내기 전에 대략 계산해서 한도를 넘으면 경고하겠습니다.
