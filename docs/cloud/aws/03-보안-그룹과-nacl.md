AWS에서 트래픽을 거르는 두 방화벽, 보안 그룹과 NACL을 정리했습니다.

## 보안 그룹 (Security Group)

**보안 그룹**은 EC2 같은 인스턴스 앞에 붙는 방화벽입니다. 허용 규칙만 적을 수 있고 적지 않은 트래픽은 모두 막힙니다. 또 **상태 저장(stateful)** 방식이라 들어오는 요청을 허용하면 그 응답은 아웃바운드 규칙과 관계없이 자동으로 나갑니다.

B3-1의 보안 그룹 규칙은 이렇습니다.

| 방향 | 프로토콜 | 포트 | 출발지/목적지 | 이유 |
|---|---|---|---|---|
| 인바운드 | TCP | 80 | 0.0.0.0/0 | 웹 페이지는 누구나 봐야 함 |
| 인바운드 | TCP | 22 | 내 IP/32 | SSH는 관리용이라 내 IP 하나만 |
| 아웃바운드 | 전체 | 전체 | 0.0.0.0/0 | 패키지 설치 등 밖으로 나가는 통신 |

`/32`는 IP 주소 딱 하나라는 뜻입니다. SSH를 전체에 열면 비밀번호·키 대입 공격에 그대로 노출되기 때문에 내 IP만 허용했습니다. 포트 전체(0-65535)를 여는 설정은 쓰지 않았습니다.

## NACL (네트워크 ACL)

**NACL**은 서브넷 경계에서 트래픽을 거르는 방화벽입니다. 허용과 거부를 모두 적을 수 있고 규칙 번호가 작은 것부터 차례로 검사합니다. **상태 비저장(stateless)** 방식이라 응답 트래픽도 따로 허용해 줘야 합니다.

| 구분 | 보안 그룹 | NACL |
|---|---|---|
| 적용 단위 | 인스턴스(네트워크 인터페이스) | 서브넷 |
| 규칙 | 허용만 | 허용과 거부 |
| 상태 | 상태 저장: 응답 자동 허용 | 상태 비저장: 응답도 규칙 필요 |
| 검사 순서 | 모든 규칙을 함께 보고 판단 | 번호 순서대로, 처음 맞는 규칙 적용 |
| B3-1에서 | 직접 만들어 사용 | 기본 NACL(전체 허용) 그대로 |

보통은 보안 그룹으로 세밀하게 거르고 NACL은 특정 IP 대역을 서브넷 단위로 통째로 막을 때 씁니다.

## 면접에서 나올 만한 질문

### Q. 보안 그룹과 NACL은 어떻게 다른가요?

AWS 네트워크 질문에서 가장 자주 나오는 비교입니다.

> 보안 그룹은 인스턴스 단위로 붙고 허용 규칙만 있으며 상태 저장 방식이라 허용한 요청의 응답은 자동으로 나갑니다. NACL은 서브넷 단위로 붙고 허용과 거부를 모두 적을 수 있으며 상태 비저장이라 응답 트래픽도 규칙으로 열어야 합니다. B3-1에서는 보안 그룹으로 HTTP 80은 전체에, SSH 22는 내 IP 하나에만 열었고 NACL은 기본값을 썼습니다.

### 꼬리질문

- 아웃바운드를 전부 열어 둔 것은 괜찮나요?
  → 학습용으로는 기본값을 썼지만 서버가 악성 코드에 감염되면 밖으로 데이터를 보낼 수 있습니다. 실무에서는 필요한 목적지와 포트만 여는 편이 안전합니다.
