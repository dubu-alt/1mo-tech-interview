격리된 VPC를 인터넷과 잇는 인터넷 게이트웨이와, 패킷이 갈 길을 정하는 라우팅 테이블을 정리했습니다.

## 인터넷 게이트웨이 (IGW)

**인터넷 게이트웨이**는 VPC와 인터넷 사이의 출입구입니다. VPC 하나에 하나만 붙일 수 있고 인스턴스의 사설 IP와 퍼블릭 IP를 서로 바꿔 주는 일도 맡습니다. IGW를 만들기만 하고 VPC에 연결(attach)하지 않으면 아무 일도 하지 않습니다.

## 라우팅 테이블

**라우팅 테이블**은 "이 목적지로 가는 패킷은 어디로 보낸다"를 적은 표입니다. 서브넷은 라우팅 테이블 하나와 연결되고 패킷은 목적지와 가장 구체적으로 맞는 경로를 따라갑니다.

| 목적지 | 대상 | 뜻 |
|---|---|---|
| `10.0.0.0/16` | local | VPC 안끼리는 바로 통신 (자동으로 생김) |
| `0.0.0.0/0` | 인터넷 게이트웨이 | 그 밖의 모든 주소는 인터넷으로 |

`0.0.0.0/0`은 "나머지 전부"를 뜻하는 기본 경로(default route)입니다. 이 경로가 없으면 요청이 VPC 안에서만 돌고 인터넷으로 나가지 못합니다.

B3-1에서는 라우팅 테이블을 새로 만들어 `0.0.0.0/0 → IGW` 경로를 넣고 퍼블릭 서브넷에 연결(associate)했습니다. IGW 연결, 경로 추가, 서브넷 연결 중 하나라도 빠지면 접속이 안 됩니다.

## NAT 게이트웨이

**NAT 게이트웨이**는 프라이빗 서브넷의 서버가 밖으로 나가는 요청(패키지 설치, 외부 API 호출)만 할 수 있게 해 주는 장치입니다. 밖에서 먼저 들어오는 연결은 받지 않습니다.

| 구분 | 인터넷 게이트웨이 | NAT 게이트웨이 |
|---|---|---|
| 방향 | 들어오고 나가기 모두 | 안에서 밖으로 나가기만 |
| 붙는 곳 | VPC | 퍼블릭 서브넷 (프라이빗 서브넷의 경로가 가리킴) |
| 요금 | 없음 | 시간당 요금 + 처리한 데이터 양만큼 |

B3-1은 프라이빗 서브넷이 없어서 NAT 게이트웨이를 만들지 않았습니다. 네트워크 기초를 익히는 게 목표였고 NAT 게이트웨이는 프리 티어가 아니라서 뺐습니다.

## 면접에서 나올 만한 질문

### Q. 인터넷 게이트웨이를 만들었는데도 외부에서 접속이 안 된다면 무엇을 확인하나요?

IGW 하나만 있으면 된다고 생각하는지, 경로 전체를 아는지 봅니다.

> IGW가 VPC에 연결(attach)됐는지 먼저 봅니다. 그다음 서브넷에 연결된 라우팅 테이블에 `0.0.0.0/0 → IGW` 경로가 있는지, 그 라우팅 테이블이 실제로 그 서브넷에 연결됐는지 확인합니다. 라우팅이 맞으면 인스턴스의 퍼블릭 IP, 보안 그룹 인바운드 규칙, 서버 프로세스 순서로 내려갑니다.

### 꼬리질문

- 인터넷 게이트웨이와 NAT 게이트웨이는 어떻게 다른가요?
  → IGW는 들어오고 나가는 통신을 모두 잇고 NAT 게이트웨이는 프라이빗 서브넷이 밖으로 나가는 통신만 허용합니다.
