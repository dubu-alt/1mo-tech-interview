AWS에서 서버를 띄우기 전에 먼저 만드는 네트워크, VPC와 서브넷을 정리했습니다.

## 리전과 가용 영역

**리전(Region)**은 AWS 데이터센터가 모여 있는 지역입니다. 서울은 `ap-northeast-2`입니다. **가용 영역(AZ)**은 한 리전 안에 떨어져 있는 독립된 데이터센터 묶음으로, 서울에는 `ap-northeast-2a`, `2b` 같은 AZ가 있습니다. 한 AZ에 문제가 생겨도 다른 AZ는 살아 있도록 나눠 둔 것이라, 서비스를 여러 AZ에 나눠 두면 장애에 강해집니다.

B3-1에서는 서울 리전의 AZ 하나(`ap-northeast-2a`)만 썼습니다.

## VPC

**VPC(Virtual Private Cloud)**는 AWS 안에 만드는 나만의 격리된 네트워크입니다. 처음 만든 VPC는 바깥과 연결되어 있지 않아서 인터넷과 통신하려면 인터넷 게이트웨이와 라우팅을 직접 붙여야 합니다.

## CIDR로 IP 범위 정하기

VPC와 서브넷은 쓸 IP 범위를 CIDR로 적습니다. `/` 뒤 숫자는 앞에서부터 고정된 비트 수이고 숫자가 작을수록 범위가 넓습니다.

| 표기 | 고정 비트 | IP 개수 | B3-1에서 |
|---|---|---|---|
| `10.0.0.0/16` | 앞 16비트 | 65,536개 | VPC 전체 |
| `10.0.1.0/24` | 앞 24비트 | 256개 | 퍼블릭 서브넷 |

AWS는 서브넷마다 IP 5개(네트워크 주소, VPC 라우터, DNS, 예약 1개, 브로드캐스트)를 미리 가져가서 `/24` 서브넷에서 실제로 쓸 수 있는 IP는 251개입니다.

## 서브넷: 퍼블릭과 프라이빗

**서브넷**은 VPC의 IP 범위를 잘게 나눈 구역이고 서브넷 하나는 AZ 하나에 속합니다. 퍼블릭과 프라이빗은 서브넷을 만들 때 고르는 옵션이 아니라 **라우팅 테이블**로 결정됩니다.

| 구분 | 라우팅 | 쓰임 |
|---|---|---|
| 퍼블릭 서브넷 | `0.0.0.0/0 → 인터넷 게이트웨이` 경로가 있음 | 웹 서버, 로드 밸런서처럼 밖에서 들어와야 하는 것 |
| 프라이빗 서브넷 | 인터넷 게이트웨이 경로가 없음 | DB, 내부 서버처럼 밖에서 직접 닿으면 안 되는 것 |

퍼블릭 서브넷이라도 인스턴스에 **퍼블릭 IP**가 없으면 밖에서 접속할 수 없습니다. B3-1에서는 서브넷에 `map-public-ip-on-launch`를 켜서 EC2가 만들어질 때 퍼블릭 IP를 자동으로 받게 했습니다.

## 면접에서 나올 만한 질문

### Q. 퍼블릭 서브넷과 프라이빗 서브넷은 무엇으로 나뉘나요?

이름만 외웠는지, 실제로 무엇이 둘을 가르는지 아는지 봅니다.

> 서브넷에 연결된 라우팅 테이블에 인터넷 게이트웨이로 가는 경로(`0.0.0.0/0 → IGW`)가 있으면 퍼블릭, 없으면 프라이빗입니다. 서브넷 자체에 퍼블릭이라는 설정이 있는 것은 아닙니다. 퍼블릭 서브넷이라도 인스턴스에 퍼블릭 IP가 있어야 밖에서 접속할 수 있어서 B3-1에서는 서브넷의 퍼블릭 IP 자동 할당도 켰습니다.

### 꼬리질문

- `/24` 서브넷에서 EC2에 줄 수 있는 IP는 몇 개인가요?
  → 256개 중 AWS가 5개를 예약해서 251개입니다.
- 실무에서는 웹 서버를 어느 서브넷에 두나요?
  → 보통 로드 밸런서만 퍼블릭 서브넷에 두고 웹 서버와 DB는 프라이빗 서브넷에 둡니다. B3-1은 학습용이라 EC2를 퍼블릭 서브넷에 바로 뒀습니다.
