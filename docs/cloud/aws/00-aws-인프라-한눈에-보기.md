코디세이 B3-1 미션에서 AWS에 네트워크부터 직접 만들고 Nginx 웹 서버를 올려 외부에서 접속되게 했습니다. 이 페이지에서 전체 구조와 개념을 먼저 훑고 자세한 내용은 개념별 글에서 보면 됩니다.

## 무엇을 만들었나

AWS 서울 리전에 VPC를 새로 만들고 그 안의 퍼블릭 서브넷에 EC2 한 대를 띄워 Nginx로 웹 페이지와 헬스체크(`/health`)를 응답하게 했습니다. 보안 그룹은 필요한 포트만 열고 작업용 IAM 사용자에게는 실습에 필요한 권한만 줬습니다. 구축과 정리는 AWS CLI 셸 스크립트로 자동화했습니다.

![인터넷에서 IGW, 라우팅 테이블, 퍼블릭 서브넷, 보안 그룹을 거쳐 EC2의 Nginx까지 가는 B3-1 아키텍처](/images/cloud/aws-architecture.png)
*그림: B3-1 아키텍처. 오른쪽 IAM 상자의 DENY는 허용 목록에 넣지 않아 막힌다는 뜻이고 정책에 Deny 문장을 따로 쓴 것은 아닙니다.*

| 구성 요소 | 이름 | 설정 |
|---|---|---|
| VPC | cloud-lab-vpc | 10.0.0.0/16 |
| 퍼블릭 서브넷 | cloud-lab-public-subnet | 10.0.1.0/24 (ap-northeast-2a) |
| 인터넷 게이트웨이 | cloud-lab-igw | VPC에 연결 |
| 라우팅 테이블 | cloud-lab-public-rt | 0.0.0.0/0 → IGW |
| 보안 그룹 | cloud-lab-web-sg | HTTP 80 전체, SSH 22 내 IP만 |
| EC2 | cloud-lab-web-server | t2.micro, Ubuntu 22.04 LTS |
| 웹 서버 | Nginx | 80번 포트, `/health` 응답 |

## 요청이 들어오는 길

```
사용자 (인터넷)
 → 인터넷 게이트웨이 (VPC의 출입구)
 → 라우팅 테이블 (0.0.0.0/0 → IGW)
 → 퍼블릭 서브넷 (10.0.1.0/24)
 → 보안 그룹 (TCP 80 허용?)
 → EC2 → Nginx → 응답
```

이 중 하나만 빠져도 외부에서 접속이 안 됩니다. 그래서 접속이 안 될 때도 이 순서대로 하나씩 확인합니다.
