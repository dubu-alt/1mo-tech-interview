---
title: "함수 종속성과 정규화"
---

정규화의 기준이 되는 함수 종속성을 먼저 보고, 이를 하나씩 없애 나가는 정규화 단계(1NF → BCNF)로 이어서 정리했습니다.

## 함수 종속성: X를 알면 Y를 알 수 있다

**함수 종속성**은 "속성 X의 값을 알면 속성 Y의 값이 자동으로 하나로 정해진다"는 관계입니다. `X → Y`로 표기하고, X를 **결정자**, Y를 **종속자**라고 부릅니다.

주의할 점: 화살표는 한쪽 방향으로만 성립합니다. `X → Y`가 성립한다고 `Y → X`도 성립하는 건 아닙니다. (학번을 알면 이름을 알 수 있지만, 이름만으로는 학번을 알 수 없는 것처럼요.)

정규화를 이해하려면 세 가지 종속을 구분할 수 있어야 합니다. 기본키가 [학번, 과목코드] 두 개로 이루어진 성적 테이블을 예로 들어보겠습니다.

| 학번 | 과목코드 | 학생이름 | 성적 | 학과 | 학과사무실 |
|---|---|---|---|---|---|
| 100 | C1 | 철수 | A | 컴공 | 3동 401호 |
| 100 | C2 | 철수 | B | 컴공 | 3동 401호 |

- **완전 함수 종속**: 기본키 **전체**에 종속되는 경우. `[학번, 과목코드] → 성적`은 학번과 과목코드가 둘 다 있어야 성적이 정해지므로 완전 함수 종속입니다.
- **부분 함수 종속**: 기본키의 **일부**에만 종속되는 경우. `학번 → 학생이름`은 과목코드 없이 학번만으로도 정해지므로 부분 함수 종속입니다.
- **이행적 함수 종속**: `X → Y`이고 `Y → Z`이면 결과적으로 `X → Z`가 되는 경우. `학번 → 학과`이고 `학과 → 학과사무실`이므로, `학번 → 학과사무실`도 성립합니다. 학번이 학과사무실을 "간접적으로" 결정하는 셈입니다.

이 세 가지 종속을 하나씩 없애 나가는 과정이 바로 다음에 나올 **정규화**입니다.

## 정규화: 중복 데이터를 안 두는 기술

**정규화**는 한마디로 "같은 정보를 여러 곳에 중복해서 저장하지 않도록 테이블을 쪼개는 작업"입니다. 중복이 있으면 하나만 수정했을 때 나머지가 낡은 값으로 남는 문제(이상현상)가 생기는데, 정규화는 이걸 예방합니다. 단계가 올라갈수록 규칙이 하나씩 더 붙습니다.

### 1정규형 (1NF): 한 칸엔 값 하나만

모든 속성 값이 **원자값**이어야 합니다. 한 학생의 "취미" 칸에 "축구, 독서"가 같이 들어있다면, 이걸 행 단위로 쪼개야 합니다.

### 2정규형 (2NF): 부분 함수 종속 제거

1NF를 만족하고, 기본키 **일부**에만 종속되는 속성을 별도 테이블로 뺍니다. [학번, 과목코드]가 기본키인 테이블에서 [학번]에만 종속되는 [학생이름]을 별도의 "학생" 테이블로 분리하는 식입니다. (기본키가 원래 속성 1개뿐이면 이 문제는 자동으로 해결됩니다.)

### 3정규형 (3NF): 이행적 함수 종속 제거

2NF를 만족하고, 기본키가 아닌 속성끼리 원인-결과로 얽혀 있는 것도 분리합니다. `학번 → 학과 → 학과사무실` 관계라면, [학과, 학과사무실]을 별도 테이블로 뺍니다.

### BCNF: 결정자는 전부 후보키여야 함

3NF까지 만족해도 예외적으로 남는 문제가 있습니다. [학번, 과목명]이 복합 기본키인 테이블에서, 각 과목을 가르치는 [교수]가 한 명뿐이고 그 교수가 오직 그 과목만 가르친다고 하면 `교수 → 과목명`이 성립합니다. 그런데 [교수]는 후보키가 아닙니다(학번을 구분 못 함). 이렇게 **결정자인데 후보키가 아닌 경우**가 있으면 BCNF 위반이고, 해결책은 `[학번, 교수]`와 `[교수, 과목명]` 두 테이블로 다시 쪼개는 것입니다.

```
정규화 정도 ─────────────────▶
1NF → 2NF → 3NF → BCNF
(원자값)  (부분종속×) (이행종속×) (결정자=후보키)
```

정규화를 많이 할수록 중복은 줄지만, 조회할 때 조인해야 할 테이블 수가 늘어나는 트레이드오프가 있습니다.

## 정리

| 단계 | 조건 | 없애는 것 |
| --- | --- | --- |
| 1NF | 모든 속성 값이 원자값 | 한 칸에 여러 값 |
| 2NF | 1NF + 기본키 전체에 완전 함수 종속 | 부분 함수 종속 |
| 3NF | 2NF + 키가 아닌 속성끼리 종속 없음 | 이행적 함수 종속 |
| BCNF | 모든 결정자가 후보키 | 후보키가 아닌 결정자 |

- 함수 종속 `X → Y`: X(결정자)를 알면 Y(종속자)가 하나로 정해지며, 한 방향으로만 성립합니다.
- 정규화할수록 중복은 줄지만 조회 시 조인할 테이블 수가 늘어납니다.
