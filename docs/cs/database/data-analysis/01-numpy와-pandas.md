A1-1에서 데이터를 다룰 때 쓴 두 라이브러리를 정리했습니다. NumPy는 배열 계산을, Pandas는 표 데이터 정리를 맡았습니다.

## NumPy와 벡터 연산

**NumPy**는 숫자 배열을 빠르게 계산하는 파이썬 라이브러리입니다. 핵심은 `ndarray`라는 다차원 배열입니다. 같은 자료형의 값을 메모리에 촘촘히 붙여 저장하기 때문에, 파이썬 `for` 문으로 값을 하나씩 꺼내 계산하는 대신 배열 전체에 연산을 한 번에 적용할 수 있습니다. 이것을 **벡터 연산**이라고 부릅니다.

```python
import numpy as np

prices = np.array([1200, 3500, 800])
prices * 1.1        # 세 값에 한 번에 10%를 더함 → [1320. 3850.  880.]
```

A1-1에서는 이미지 6만 장의 평균과 표준편차를 반복문 없이 구할 때 썼습니다([피처 엔지니어링](./04-피처-엔지니어링) 참고). RFM 점수를 매길 때는 `np.searchsorted`(값이 몇 번째 구간에 들어가는지 찾기)를, 조건별로 그룹 이름을 붙일 때는 `np.select`를 썼습니다.

## Pandas

**Pandas**는 엑셀처럼 행과 열이 있는 표 데이터를 다루는 라이브러리입니다. 표 전체를 **DataFrame**, 열 하나를 **Series**라고 부릅니다. 내부는 NumPy 배열 위에 만들어져 있어서 계산이 빠르고 그 위에 열 이름, 날짜 처리, 결측치 처리, 그룹별 집계 같은 기능이 붙어 있습니다.

| 하고 싶은 일 | Pandas 코드 |
|---|---|
| 엑셀·CSV 읽기 | `pd.read_excel()`, `pd.read_csv()` |
| 구조 훑어보기 | `info()`, `describe()`, `head()` |
| 빈칸 세기 / 채우기 | `isna().sum()`, `fillna()` |
| 똑같은 행 지우기 | `drop_duplicates()` |
| 그룹별 집계 | `groupby("customer_id").agg(...)` |
| 사분위수 / 범위 제한 | `quantile([0.25, 0.75])`, `clip()` |

A1-1에서는 엑셀 시트 2개를 합쳐 1,067,371행 × 8열 표를 만들고 다음 실행부터 빨리 읽도록 CSV로 저장했습니다.

## NumPy와 Pandas 비교

| 구분 | NumPy | Pandas |
|---|---|---|
| 다루는 것 | 같은 자료형의 숫자 배열 | 이름 붙은 열이 있는 표 (열마다 자료형이 달라도 됨) |
| 기본 단위 | `ndarray` | `DataFrame`, `Series` |
| 잘하는 일 | 대량 수치 계산, 이미지·행렬 | 파일 읽기, 정제, 결측치, 그룹 집계, 날짜 |
| A1-1에서 | 이미지 6만 장 수치화, RFM 점수 구간 | 거래 107만 건 정제, 고객별 집계 |

## 면접에서 나올 만한 질문

### Q. NumPy 배열 연산은 왜 파이썬 반복문보다 빠른가요?

NumPy를 썼다는 사실보다, 왜 빨라지는지 설명할 수 있는지를 보는 질문입니다.

> `ndarray`는 같은 자료형의 값을 메모리에 연속으로 저장합니다. 그래서 값마다 자료형을 확인할 필요 없이, C로 구현된 내부 반복문이 배열 전체를 한 번에 처리합니다. 파이썬 `for` 문은 원소 하나를 꺼낼 때마다 객체를 확인하고 인터프리터를 거치기 때문에 느립니다. A1-1에서는 이미지 6만 장의 평균과 표준편차를 반복문 없이 `mean(axis=(1, 2))`, `std(axis=(1, 2))` 한 줄씩으로 구했습니다.

"C로 만들어져서 빠릅니다"라고만 답하면 부족합니다. 같은 자료형이 연속으로 저장돼 있어서 한 번에 처리할 수 있다는 점까지 이어서 말하는 게 좋습니다.
