분석 결과를 전략으로 옮기는 형식과 코드 구조, 그리고 A1-1 분석의 한계를 정리했습니다.

## 근거·실행·검증

인사이트 하나를 세 부분으로 나눠 씁니다.

| 부분 | 들어갈 내용 | A1-1 예시 |
|---|---|---|
| 근거 | 수치나 그래프 | VIP 21.7%가 구매 금액의 68.0% |
| 실행 | 대상 세그먼트, 실행 방법, 기대 효과 | 성수기 전 VIP 멤버십 혜택 강화 |
| 검증 | 추가로 필요한 데이터 또는 반증 가능성 | 소수 초대형 고객을 빼도 68%가 유지되는지 확인 |

반증 가능성은 이 결론이 틀릴 수 있는 경우를 미리 적는 것입니다. 숫자 하나로 결론을 단정하지 않게 막아 줍니다.

## 파이프라인 클래스

파이프라인은 불러오기 → 정제 → 피처 → 분석처럼 정해진 순서로 데이터를 흘려보내는 흐름입니다. 노트북 셀에 코드를 흩어 두지 않고 단계를 클래스의 메서드로 묶으면 다른 데이터에도 다시 쓸 수 있습니다. 이상치 임계값(1.5)이나 대치 방법(최빈값·중앙값·평균)을 인자로 받게 하면 값을 바꿔 가며 실험하기도 쉽습니다.

```python
a = DataAnalyzer()
a.load_data()
a.handle_missing_values(target_col="description", group_col="stock_code", strategy="mode")
a.clean_data()
outliers = a.detect_outliers("quantity", threshold=1.5)
rfm = a.calculate_rfm()
```

## A1-1 분석의 한계

- **이미지는 진짜 상품 사진이 아닙니다.** 거래 데이터에 이미지가 없어서 옷 이미지를 난수(시드 42)로 상품에 붙였습니다. NumPy 연습용이라 인사이트에는 쓰지 않았습니다.
- **2년치 데이터뿐입니다.** 10~11월에 매출이 몰리는 패턴이 매년 반복되는지 구분하기 어렵습니다. 마지막 달(2011-12)은 9일치라서 월별 추이에서 뺐습니다.
- **취소된 원래 주문은 남아 있습니다.** 취소 행(`C`)만 지웠기 때문에, 80,995개를 주문하고 12분 뒤 전량 취소한 고객의 구매 금액이 약 168,470으로 부풀려졌습니다.
- **완전 중복 행을 모두 지웠습니다.** 같은 주문에서 같은 상품을 두 번 입력한 정상 행까지 지웠을 수 있습니다.
- **고객 번호가 없는 거래는 RFM에서 빠졌습니다.** 이 거래들이 특정 유형의 고객에게 몰려 있다면 그룹 비율이 달라질 수 있습니다.
- **그룹 기준은 제가 정한 규칙이고 점수는 상대평가입니다.** 기준을 바꾸거나 다른 기간 데이터를 쓰면 그룹별 고객 수가 달라집니다.
- **평균이 소수 고객에게 끌려갑니다.** VIP의 평균 구매 금액(9,276)이 중앙값(4,002)의 2.3배라서 VIP가 매출의 68%를 차지한다는 결론도 몇몇 초대형 고객의 영향일 수 있습니다.
- **기대 효과는 가정입니다.** "이탈 고객의 10%가 돌아온다면" 같은 숫자는 어림 계산이고 실제 효과는 실험 데이터가 있어야 확인할 수 있습니다.

다음에는 원래 주문과 취소 주문을 짝지어 함께 지울 생각입니다. 코호트 분석으로 이탈 고객과 계절 고객을 나누고 그룹 기준을 바꿔 가며 결과가 얼마나 흔들리는지도 확인해 보려 합니다.

## 면접에서 나올 만한 질문

### Q. 분석 코드를 노트북에 바로 쓰지 않고 클래스로 만든 이유는 무엇인가요?

분석 결과만이 아니라 코드를 다시 쓸 수 있게 설계했는지 봅니다.

> 노트북 셀에 코드를 흩어 두면 실행 순서가 꼬이기 쉽고 다른 데이터에 다시 쓰기 어렵습니다. A1-1에서는 불러오기, 결측치 처리, 정제, 이상치 탐지, RFM 계산을 `DataAnalyzer` 클래스의 메서드로 묶고 노트북에서는 메서드를 호출만 했습니다. 이상치 임계값과 결측치 대치 방법은 인자로 받게 해서 코드를 고치지 않고도 값을 바꿔 가며 결과를 비교할 수 있습니다.
