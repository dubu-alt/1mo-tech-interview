# GitHub로 코드 리뷰하기

동료가 PR을 올리고 리뷰를 요청했다고 가정해봅시다. PR 페이지의 **Files changed** 탭에 들어가면 변경된 코드가 보입니다. 빨간 줄은 삭제된 코드, 초록 줄은 추가된 코드입니다.

## 라인별 리뷰

라인 번호 오른쪽에 마우스를 올리면 `+` 버튼이 뜨고, 여기서 코멘트를 남길 수 있습니다. 단순 코멘트뿐 아니라 **suggested change** 기능으로 직접 수정안을 제안할 수도 있습니다. suggestion 블록 안에 원하는 코드를 적으면, 작성자가 버튼 한 번으로 그 제안을 그대로 반영할 수 있습니다.

## 멀티라인 리뷰

라인 번호 좌측을 클릭하고 Shift를 누른 채 다른 라인을 클릭하면 여러 줄을 노란색으로 선택할 수 있습니다. 이 상태로 코멘트를 남기면 여러 줄에 걸친 리뷰가 됩니다. 참고로 코멘트에 `#`을 입력하면 다른 PR을 검색해서 연결할 수 있습니다.

## Viewed 체크로 리뷰 진행 상황 관리하기

파일이 수십 개씩 바뀌는 PR은 뭘 봤는지 헷갈리기 쉽습니다. 파일 옆의 `Viewed` 체크박스를 누르면 해당 파일이 접히고, 이후 새 커밋에서 그 파일이 안 바뀌었다면 계속 접힌 채로 남아있습니다. 리뷰 진행률이 우측 하단 파란 바로 표시됩니다.

## 커밋 단위로 리뷰하기

PR을 논리 단위로 잘게 커밋해서 올렸다면, 커밋별 보기 기능으로 하나씩 순서대로 확인하는 것도 좋은 방법입니다. Shift로 범위를 선택하면 연속된 여러 커밋을 한 번에 볼 수도 있습니다.

## 리뷰 제출하기: Comment / Approve / Request changes

| 옵션 | 용도 |
|---|---|
| **Comment** | 의견이나 질문만 남기고 싶을 때 (승인/반려 의사 없음) |
| **Approve** | 코드에 문제없다는 승인. Branch protection에서 필수로 지정했다면 이게 있어야 머지 가능 |
| **Request changes** | 수정이 필요할 때. 이게 걸려 있으면 작성자가 새 커밋으로 반영할 때까지 머지가 막힘 |
