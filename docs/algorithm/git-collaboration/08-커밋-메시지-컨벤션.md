# Conventional Commit: 커밋 메시지 규칙

커밋 메시지는 코드 변경 사항을 빠르게 파악하는 핵심 단서입니다. 나중에 문제가 생겼을 때 원인을 추적하는 데도 큰 도움이 되죠. 이걸 체계적으로 하기 위해 만들어진 규칙이 **Conventional Commit**입니다.

형식은 다음과 같습니다.

```
<type>(<scope>): <subject>
```

- `type`: 커밋의 종류
- `scope`: 영향을 받는 범위
- `subject`: 간단한 설명 (명령형 동사로 시작)

예를 들어 로그인 화면에 이메일 인증 기능을 추가했다면:

```
feat(UserProfile): Add email verification
```

## 자주 쓰는 type

| type | 의미 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `style` | 코드 포맷팅 (로직 변화 없음) |
| `refactor` | 기능 변화 없는 코드 구조 개선 |
| `test` | 테스트 코드 추가/수정 |
| `chore` | 빌드, 설정 등 자잘한 작업 |

## 왜 굳이 이렇게까지 규칙을 지킬까?

이렇게 통일된 형식으로 커밋을 쌓으면, 나중에 `feat` 타입 커밋만 골라 모아서 Release Note를 **자동으로 생성**하는 것도 가능해집니다. 사람이 일일이 변경 이력을 정리할 필요가 없어지는 것이죠.
